# 🚧 Sprint 3.1-C — Correção SPA Routing (Cloudflare Pages)

## 🎯 Objetivo
Corrigir erro:

```
Unsafe attempt to load URL ... chrome-error://chromewebdata/
```

Garantir que o frontend (React + Vite) funcione corretamente em rotas SPA no Cloudflare Pages.

---

# 🔴 PROBLEMA

Cloudflare Pages NÃO entende rotas do React Router:

Exemplo:
- /login
- /dashboard
- /promotions

Sem configuração → retorna 404 → vira `chrome-error` → quebra app.

---

# 🛠️ SOLUÇÃO

## 1. Criar arquivos necessários

### Caminhos obrigatórios:

- `apps/web/public/_redirects`
- `apps/web/public/404.html`

### Conteúdo EXATO do `_redirects`:

```txt
/* /index.html 200
/404.html /index.html 200
```

### Conteúdo da `404.html` (pode ser idêntico ao index.html para SPA):

```html
<!DOCTYPE html>
<html lang="pt-BR">
<head>
  <meta charset="UTF-8" />
  <meta name="viewport" content="width=device-width, initial-scale=1.0" />
  <title>Promos Prado</title>
  <script>
    // Redirect to index.html for SPA routing
    window.location.href = '/';
  </script>
</head>
<body>
  <noscript>Você precisa habilitar JavaScript para executar este aplicativo.</noscript>
  <div id="root"></div>
</body>
</html>
```

---

## 2. Garantir build inclui os arquivos

Após build:

```bash
cd apps/web
npm run build
```

### Verificar:

```
apps/web/dist/_redirects
apps/web/dist/404.html
```

Se NÃO existir → erro crítico.

---

## 3. Validar vite.config.ts

Arquivo:

```
apps/web/vite.config.ts
```

Deve conter:

```ts
export default defineConfig({
  base: '/',
})
```

---

## 4. Limpar cache e redeploy Cloudflare Pages

Após commit:

1. Push para GitHub
2. Aguardar novo deploy OU fazer redeploy manual
3. Purge cache do Cloudflare Pages (no painel ou via API)

OU:

* manual redeploy no painel com opção de limpar cache
